# D2SteamFix 한국어 설치 도우미

[D2SteamFix](https://github.com/d2checkpoint-com/D2SteamFix)(Destiny 2 프레임 끊김 완화 도구)를
한국 사용자가 쉽게 설치할 수 있도록 도와주는 보조 도구입니다.

한국인이 실제로 막히는 지점은 프로그램의 영어 메시지가 아니라
**Steam 실행 옵션에 게임 경로를 직접 타이핑해 넣는 과정**입니다.
이 도우미는 그 부분만 대신합니다.

## 사용법

압축을 풀고 `D2SteamFix 설치도우미.bat` 을 더블클릭하세요(저장소에서는 `src/` 안에 있습니다).
관리자 권한은 필요 없습니다.

1. **1단계** — Steam과 Destiny 2 설치 위치를 자동으로 찾습니다.
   못 찾으면 `게임 폴더 직접 지정`으로 알려주면 됩니다. (다음부터 기억합니다)
2. **2단계** — `다운로드 안내 열기`(또는 `다운로드 주소 복사`)로 `steamfix.exe`를 받고,
   `게임 폴더 열기`로 열린 폴더에 넣습니다.
3. **3단계** — `자동으로 설정하기`를 누르면 Steam 실행 옵션이 기록됩니다.
   직접 넣고 싶으면 `복사해서 직접 넣기`를 쓰세요.

되돌리려면 `설정 되돌리기`를 누르면 됩니다.
적용할 때와 마찬가지로 끝나면 완료 창이 뜹니다.
되돌릴 설정이 없으면 Steam을 끄기 전에 먼저 알려주므로 헛되이 Steam이 종료되지 않습니다.

## 알아두어야 할 것

- **`steamfix.exe`를 대신 내려받지 않습니다.** 제작자가 배포하는 원본을 그대로 쓰게 합니다.
  출처를 알 수 없는 재배포본을 만들지 않기 위한 의도적인 설계입니다.
- **GitHub 릴리스 탭은 비어 있습니다.** 이 프로젝트는 릴리스나 태그를 하나도 올려두지 않았고,
  배포는 제작자 서버(`https://pkg.d2checkpoint.com/D2SteamFix/steamfix.exe`)에서만 이루어집니다.
  릴리스 페이지를 열면 "There aren't any releases here"만 보이므로,
  도우미는 README의 Installation 항목으로 안내합니다.
- **받은 파일이 실행 파일인지 확인합니다.** 브라우저가 오류 페이지를 `steamfix.exe`라는
  이름으로 저장해 버리는 사고가 있어, PE 서명(`MZ`)을 확인해 걸러냅니다.
- **Steam이 켜져 있으면 설정할 수 없습니다.** Steam은 종료할 때 설정 파일을 통째로
  다시 쓰기 때문에, 켜진 상태에서 고치면 변경이 사라집니다. 도우미가 종료 여부를 묻고 처리합니다.
- **설정 파일은 고치기 전에 항상 백업합니다.**
  `%LOCALAPPDATA%\D2SteamFixHelper` 에 `localconfig-<계정ID>-<시각>.vdf.bak` 로 쌓입니다.
  1개가 약 250KB라 무한정 두면 커지므로 **최근 20개만 보관**하고 나머지는 자동으로 지웁니다
  (`$script:BackupKeep`). `Copy-Item` 이 원본의 수정 시각까지 복사하는 탓에 백업 시각이
  실제 생성 순서와 어긋나므로, 복사 직후 `LastWriteTime` 을 현재 시각으로 다시 찍습니다.
- **기존 실행 옵션은 지우지 않습니다.** 이미 `-DX12` 같은 옵션을 쓰고 있었다면
  `"...steamfix.exe" %command% -DX12` 형태로 뒤에 붙여 보존합니다. 바꾸기 전에 확인 창을 띄웁니다.
- **Steam 오버레이 기능은 동작하지 않게 됩니다.** D2SteamFix가 오버레이 DLL을 막는 방식이라
  Steam Input, 알림, 게임 녹화, 원격 플레이가 함께 꺼집니다. 원본 프로젝트의 알려진 동작입니다.
- 계정이 여러 개면 3단계에서 골라서 각각 설정할 수 있습니다.
- **창은 항상 주 모니터 가운데에 뜹니다.** WinForms 의 `CenterScreen` 은 커서가 있는
  모니터를 기준으로 삼아서, 모니터가 여러 대면 창이 다른 화면에 떠 실행이 안 된 것처럼
  보입니다. 그래서 주 모니터 작업영역 중앙에 직접 배치합니다.

## 구조

저장소는 받는 사람이 헤매지 않게 나눠 두었습니다. 루트에는 **읽을 것(README)과 받을 것(zip)**
만 있고, 도우미를 이루는 파일은 `src/`, 이 문서는 `docs/` 에 있습니다.

```
README.md                     받는 사람이 읽는 안내
LICENSE                       MIT
D2SteamFix 설치도우미.zip      배포본 (src/ 의 세 파일을 폴더째 압축한 것)
.gitattributes                줄바꿈 변환 차단 (아래 인코딩 항목 참고)
src/                          도우미 본체 세 파일 + 이 문서
```

루트에 보이는 것을 최소로 두려고 이 문서도 `src/` 안에 있습니다. `.gitattributes` 는
루트에 있어야 동작해서 어쩔 수 없이 남습니다. 배포 zip 에는 이 문서가 들어가지 않습니다.

| 파일 (`src/`) | 설명 |
| --- | --- |
| `D2SteamFix 설치도우미.bat` | 실행용. 내용은 ASCII만 담습니다(cmd 코드페이지 문제 회피). |
| ↳ 콘솔 숨김 | Windows 11 기본 콘솔 호스트는 Windows Terminal 이라 `-WindowStyle Hidden` 이 무시되고, 그냥 띄우면 터미널 창이 GUI 뒤에 계속 남습니다. `conhost.exe` 를 거쳐 옛날 콘솔로 띄운 뒤 스크립트가 `GetConsoleWindow`+`ShowWindow(SW_HIDE)` 로 자기 창을 숨깁니다. 배치 자신의 창만 0.5초쯤 보였다 닫힙니다. |
| `D2SteamFixHelper.ps1` | 본체. UTF-8 **BOM 포함**으로 저장해야 합니다. |
| ↳ 중복 실행 방지 | 이름 있는 뮤텍스(`Local\D2SteamFixHelperKR-SingleInstance`)로 첫 인스턴스만 통과시킵니다. 두 번째부터는 `Show-ExistingWindow` 로 기존 창을 `SW_RESTORE` + `SetForegroundWindow` 해서 앞으로 올리고 조용히 종료합니다. 창이 둘이면 양쪽이 같은 `localconfig.vdf` 에 써서 경합이 납니다. `-SelfTest` 는 뮤텍스를 잡지 않으므로 GUI 가 떠 있어도 검사할 수 있습니다. |
| ↳ 설정 직후 실행 확인 | `자동으로 설정하기` 가 끝나면 `Test-LaunchAfterApply` 로 `steamfix.exe` 를 인자 없이 한 번 실행해 봅니다. 인자가 없으면 오버레이를 건드리기 전에 스스로 종료하므로 게임에 영향이 없고, 백신이 조용히 막는 경우를 게임을 켜 보기 전에 잡아냅니다. 판정을 창 코드에서 함수로 빼 두어 자체 검사가 세 갈래(파일 없음 · 로그 못 만듦 · 실행 자체 실패)를 다 확인합니다. |
| ↳ 종료 코드 해설 | `Get-ExitCodeNote` 가 원본 `docs/EXIT_CODES.md` 의 9개 코드를 한국어 문장으로 바꿔 줍니다(10·11·12·13·14·15·16·17·19, 18은 문서에 없음). 코드 13·14·16·17 에는 다음에 할 일도 붙습니다. 숫자만 보여 주면 백신이 막은 것인지 게임이 이미 켜져 있는 것인지 구분할 수 없습니다. |
| ↳ 컨트롤 만들기 | `New-UiLabel` / `New-UiButton` / `New-UiGroup` / `New-UiLink` 로 한 줄에 만듭니다. 좌표는 원래대로 절대 픽셀이고, 고해상도 대응은 `Form` 의 `AutoScaleMode` 가 맡습니다. 알림 창도 `Show-Note` / `Show-Failure` / `Confirm-Action` 세 가지로 묶여 있습니다. |
| `사용법 (필독).txt` | 배포용 안내문. UTF-8 BOM + CRLF (메모장 대응). |
| `D2SteamFix 설치도우미.zip` | 배포용 묶음. **루트에 둡니다.** `src/` 의 세 파일만 `D2SteamFix 설치도우미` 폴더째 압축한 것이고, README·LICENSE·이 문서는 들어가지 않습니다. **`src/` 를 고치면 이 zip 도 다시 만들어 함께 커밋해야** 저장소의 배포본이 옛 버전으로 남지 않습니다. |

`D2SteamFixHelper.ps1`은 반드시 UTF-8 BOM으로 저장하세요.
Windows PowerShell 5.1은 BOM이 없으면 한글을 ANSI로 잘못 읽습니다.

### 자체 검사

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "src/D2SteamFixHelper.ps1" -SelfTest
```

검사 121개입니다. VDF 파서와 이스케이프, 실행 옵션 병합/제거, 계정 목록(가짜 `userdata` 트리),
백업 만들기와 설정 저장까지 확인하고, 마지막에 실제 `localconfig.vdf`의 **사본**에 써 보면서
다른 데이터가 손상되지 않는지 봅니다. 원본은 건드리지 않습니다.

백업·설정 검사는 `$script:StateDir` 를 임시 폴더로 갈아 끼운 뒤 되돌리므로
실제 백업 폴더(`%LOCALAPPDATA%\D2SteamFixHelper`)에는 아무것도 남지 않습니다.

마지막 항목(실제 `localconfig.vdf` 사본 검증)은 **Steam 이 켜져 있으면 검사 도중에 원본을
다시 씁니다.** 그래서 내용만 견주면 Steam 이 쓴 것까지 우리 잘못으로 잡힙니다(실제로 그렇게
실패한 적이 있습니다). 파일이 바뀐 경우에는 '우리 검사용 값이 원본에 들어가지 않았는지'로
확인하고 넘어갑니다. 노란 글씨로 그 사실을 알려 주니, 그 줄이 보이면 정상입니다.

`$null` 과 빈 문자열은 `Assert-Null` 로 따로 검사합니다. `Assert-Equal` 은 문자열로
견주기 때문에 둘을 구분하지 못하는데, 실행 옵션 읽기에서는 이 차이가
'구조를 못 읽음(오류)' 과 '옵션이 비어 있음(정상)' 을 갈라놓습니다.

### GUI 를 고쳤을 때 확인하는 방법

자체 검사는 창을 만드는 코드까지 보지는 못합니다. 컨트롤 배치를 건드렸으면
`PrintWindow` 로 창을 PNG 로 찍어 이전 것과 픽셀 단위로 견주는 편이 확실합니다.
단, **첫 캡처는 그룹박스 테두리를 놓치는 일이 있습니다.** 그래서 고치기 전 코드로
두 번 찍어 서로 비교해 노이즈 바닥을 먼저 잡고, 그다음에 고친 코드와 견주어야 합니다.
로그 칸의 시각(초)은 실행마다 달라지므로 그 부분(대략 `y 575~598`)의 차이는 정상입니다.

### 왜 직접 VDF 파서를 넣었는가

Steam의 `localconfig.vdf`에는 앱 ID와 똑같은 문자열이 실행 옵션과 무관한 위치에도 나옵니다.
실제로 이 PC의 파일에서 첫 번째 `"1085660"`은 통계 블록의 값이고,
실행 옵션이 있는 `apps` 블록은 한참 뒤에 있습니다.
문자열 검색으로 고치면 엉뚱한 데이터를 망가뜨리므로,
`UserLocalConfigStore > Software > Valve > Steam > apps` 경로를 실제로 따라 내려갑니다.
